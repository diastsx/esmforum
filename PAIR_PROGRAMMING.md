# Planejamento de Pair Programming

## Contexto

O projeto está sendo desenvolvido individualmente. Por isso, o pair programming não será utilizado diretamente nesta implementação.

Em um desenvolvimento em dupla, a prática poderia ser aplicada às novas funcionalidades, aos testes e às refatorações do backend e do frontend.

## Estratégia

As sessões seriam realizadas de forma síncrona, com os dois participantes trabalhando sobre a mesma tarefa.

Os papéis seriam:

- **Driver:** escreve o código e executa comandos e testes;
- **Navigator:** acompanha a implementação, revisa as decisões e identifica possíveis problemas.

Os papéis seriam alternados aproximadamente a cada 30 minutos ou após a conclusão de uma pequena etapa da tarefa.

Antes de iniciar uma alteração, a dupla definiria o comportamento esperado. Ao final, ambos participariam da execução dos testes e da revisão do código.

## Ferramentas

Seriam utilizadas:

- Visual Studio Code;
- VS Code Live Share;
- Discord ou Google Meet;
- Git e GitHub.

O Live Share permitiria que os dois desenvolvedores acompanhassem e editassem a mesma sessão de código, enquanto o GitHub seria utilizado para versionamento e acompanhamento das funcionalidades.

## Aplicação no ESM Forum

O pair programming poderia ser utilizado principalmente em:

- implementação das novas funcionalidades;
- alterações no modelo de dados;
- integração entre backend e frontend;
- escrita e revisão de testes;
- refatorações relacionadas a SOLID e padrões de projeto.

Durante essas atividades, o navigator poderia acompanhar tanto a correção da implementação quanto a aderência aos requisitos e à arquitetura do projeto.
